# Harness 安全边界与威胁模型

> 设计要求，非安全验收报告。DeepSeek Harness 上游处于预览阶段且尚未完成安全审计；不能把其内置权限或 Docker 资源限额当作完整可信边界。

## 保护资产与主要威胁

| 资产 | 威胁 | 基本控制 |
| --- | --- | --- |
| 交易账户/实盘订单 | AI 或恶意插件调用交易能力 | Harness 无生产凭据、无生产写权限；Platform 独立审批，Engine 自身核验 |
| 租户历史/私有研究数据 | 越权读取、模型上下文泄露、网络外传 | 资源级租户授权、最小数据快照、受控出网、模型数据政策 |
| Host 与 Docker | Shell/包安装/生成代码提权或横向移动 | 独立执行容器/VM、非 root、无 Docker socket、只挂载必要目录 |
| SeeAlpha Web | 生成的 HTML/JS 或 Markdown 执行恶意脚本 | 安全渲染、严格 sandbox/CSP、隔离源、无主站凭据 |
| 任务与研究证据 | 伪造成功、重复操作、越权下载、损坏成果 | 幂等任务、权限复核、校验和、日志与状态审计 |

输入数据、检索内容、模型输出、第三方代码、插件及研究成果均是不可信输入；**提示词不能取代权限验证**。

## 执行环境最低安全基线（实施时验证）

- 研究工作负载使用专属工作区、专属 Harness home 和最低特权身份；容器 root 文件系统尽可能只读，仅批准的临时/成果目录可写。
- 禁止 `--privileged`、宿主 PID/网络、Docker socket、SSH Agent、生产密钥目录及非必要宿主挂载；移除 Linux capabilities，启用 `no-new-privileges`、seccomp/AppArmor 等可用限制。
- 设置 CPU、内存、PIDs、任务时限、磁盘空间和输出大小上限；限制外部网络到必要模型出口及经授权的研究 API。网络隔离需实际测试，不以 compose 网络名称推断安全。
- 大量未经审查的第三方插件或客户提供的任意代码，不能仅依靠 Docker 实现强隔离；按风险采用独立 VM、宿主隔离和网络策略。
- **不要把模型 API Key 或其他高价值凭据直接注入可任意执行 Shell 的进程环境。** 优先使用由可信网关代持密钥、配额化的模型访问能力；在实现前明确残余泄露风险。
- 持久状态、Session、日志、输入提示词、工具记录与输出成果均按租户隔离，设置访问审计与保留/删除政策；不记录明文 Token。注意上游 SDK Profile 可能把会话内容纳入后续模型请求。

## Engine 与数据接入

- 平台授权必须绑定主体、租户、任务、资源、操作、用途、有效期及预算；Engine 单独验证，不信任请求体中的裸 `tenant_id`。
- 研究默认只读；开发回测采用受控任务接口。禁止 Harness 直接调用生产下单、撤单、策略启停或执行管理接口。
- 不能向 Agent 暴露通用 Engine v2 内部令牌、平台管理员密钥、交易所密钥，不能把生产 Engine 数据卷挂载为研究工作区。
- 对大数据使用租户限定的**不可变只读快照**，附来源、时间范围、质量/缺口、格式版本、内容校验和与到期策略；快照不应成为新的共享越权数据通道。
- 回测结果中区分模拟与实盘事实，不使用回测验证冒充实盘安全验收。

## 成果与审批

1. Harness 生成的脚本、策略包、回测报告、HTML 均是**草稿/不可信成果**。
2. 静态检查、隔离运行、行为测试和模拟回测只是初步验收，不能证实任意 Python 代码在生产 Engine 中安全。
3. 正式发布和实盘启用由 Platform 经过单独审批、版本固定和风险门禁，Harness 不得自行获取审批权限。
4. 动态 HTML/JS 在与 SeeAlpha 主站隔离的 Origin 中显示；sandbox 不允许继承同源与任意导航/弹窗权限，CSP 及网络访问要可验证，内容读取须按租户复核授权。
5. 向用户展示工具执行摘要和研究证据，但过滤访问令牌、密钥、敏感文件路径及不应被分享的私有数据。

## 最小验收场景

- 跨租户读取与伪造授权必须拒绝；过期、撤销、错误用途的能力必须拒绝。
- Harness 无法访问生产订单接口、Docker socket、宿主敏感目录；外部网络白名单以实际测试证实。
- 路径穿越、symlink、巨型输出、格式伪装、恶意 Artifact JS 与工具注入均受到边界限制。
- 取消、断连、超时、容器回收、任务重试不导致越权恢复或重复提交交易指令。
- 研究结果、快照和事件只能在当前租户及被授权任务下读取。
